## 1. 总体流程（已确认）

```text
用户 → Project Copilot：确认需求、明确参数、拆任务、写 Brief
     → Task Orchestrator：并行派发、计时、重试、记账
     → Lab / Research / Procurement Specialist：各自独立完成，交回 Artifact
     → 规则校验（确定性代码）：通过 / 不通过 / 未知
     → Project Copilot：汇总成 InstrumentPlan
```

整个过程中，每一步都带同一个运行 ID，可以按这个 ID 串起全链路。

## 2. 已做的决定

### A1 记忆分层（2026-11-06 确认）

| 层 | 内容 | 存在哪里 | 是否跨项目 |
|---|---|---|---|
| 项目记忆 | 需求版本、结论、证据、方案、测试结果 | 业务数据库（Project Service） | 否 |
| 跨项目知识 | **实验室知识**（内部文档、复盘、规范）+ **经验记忆**（从项目中总结的经验） | 同一个知识库，条目带类型标签加以区分 | 是 |
| 工作记忆 | 单次运行的中间步骤、草稿 | 运行状态（用完可清） | 否 |

- 项目记忆与跨项目知识严格分开。
- Agent 自己“记住”的内容不能当作事实，使用前必须重新查证；只有业务数据库里带证据的记录才是事实。

### A2 经验记忆走晋升池（2026-11-06 确认）

经验不直接写入知识库，必须经过以下流程，**每一步都在页面上可见**：

```text
触发事件 → 候选经验 → 晋升池（自动去重、检测冲突）→ 人工审核 → 经验库
```

**触发事件**：只在以下事件发生时产生候选经验，不是每次运行都产生。

| 事件 | 例子 |
|---|---|
| 用户纠正了某个结论 | “SPEC-C 其实没有制冷” |
| 用户回答了 Copilot 的提问 | “我们优先选有 Python SDK 的厂商” |
| 同一类问题反复出现 | Vendor Gamma 的参数页连续三次缺字段 |
| 测试失败（P7） | 实测分辨率比标称差 20% |
| 项目结束时的复盘 | Copilot 汇总整个项目，起草几条经验 |

**候选经验的内容**：一句话的经验陈述；适用范围（某厂商 / 某类器件 / 某种测量 / 通用）；类型（事实型 / 方法型 / 偏好型）；证据（项目、运行、结论，必须可追溯）；支持次数。

**晋升池的自动处理**：

1. 去重：先用向量相似度（pgvector）找相近条目，再由模型判断新旧两条的关系：相同（合并，支持次数加 1）/ 更具体（作为补充）/ 矛盾（标记冲突）/ 无关（新条目）。
2. 冲突：不自动覆盖，交给人裁决；默认以实验室文档为准，经验不能覆盖人写的文档。

**人工审核**：V1 所有晋升都由人审核，可以通过、驳回或修改后通过。审核时记录支持次数、冲突情况、来源，作为以后制定自动晋升规则的数据。

**可视化**（因为数据量小，每一条经验都应当能被看清）：

- 事件流：发生了哪些触发事件，各自产生了哪些候选经验
- 候选经验卡片：内容、来源事件、原始证据链接
- 晋升池状态：被合并到哪一条、与哪一条冲突、等待审核
- 经验库：每条经验的支持次数、被检索和被采用的次数、当前活跃度

**使用规则**：Agent 检索到经验时只能当作线索，必须重新查证后才能写进结论（A1）。

**分阶段实现**：

| 阶段 | 内容 |
|---|---|
| P2 | 写进 Agent 架构设计文档 |
| P3 | 记录触发事件和候选经验；只读查看页面展示事件流和候选经验 |
| P4 | 晋升池的去重与冲突检测；经验库与知识库共用检索（pgvector） |
| P5 | 审核页面（通过 / 驳回 / 修改）、经验库页面 |
| P7 之后 | 遗忘任务；视积累的审核数据决定是否引入自动晋升 |

仍待确认：遗忘方式，见 C2。

### A8 失败案例转为考题（2026-11-06 确认方向）

除了沉淀为经验，每一个**确认过的错误**（用户纠正、测试失败、回归中发现的问题）都应当转成基准任务包里的一道新题：

```text
确认的错误 ─┬→ 候选经验 → 晋升池 → 经验库（下次希望 Agent 记得）
            └→ 新考题 → 加入基准任务包 → 之后每次修改技能或提示词都必须通过（保证不再犯）
```

- 这是数据量小的团队最有效的改进方式：考卷越积越厚，比数据越积越多更可靠。
- 新考题按基准任务包的修改规则发布新版本，不修改已用于验收的旧版本。
- 是否转成考题、如何出题，由人决定；系统负责把失败案例和它的 trace 一起整理出来。

### A3 Specialist 之间不直接沟通（2026-11-06 确认）

- 所有协作都经过 Copilot。
- **Copilot 在下发 Brief 之前，就要把参数分成两类：**
  - **指定参数**：需求明确要求的，带需求项编号、目标值和单位，例如 R04 激光功率 ≥ 450 mW。
  - **不定参数**：需求没有要求的，Specialist 可以自由选择，但需要报告实际值。
- 遇到缺参数的情况，Specialist 不去找其他 Specialist，而是**多列几个候选**，把每个候选的已知值和未知值都列清楚，交给 Copilot 决定。

### A4 Copilot 可以主动向用户提问（2026-11-06 确认）

- 规划过程中，Copilot 遇到需求有歧义、关键参数缺失、候选之间无法取舍时，可以暂停流程并向用户提问。
- 用户的回答作为证据记录下来（证据来源类型为“用户决定”），回答后流程从暂停处继续。
- 运行状态需要支持“等待用户回答”的暂停与恢复，这是 P2 选型的考察项之一。

### A5 没有数据安全限制（2026-11-06 确认）

- 实验室资料可以发送给外部模型 API，不需要本地部署模型。
- 模型供应商的选择（D2）只需考虑效果和成本。

### A6 不允许运行中自我修改（已确认）

- Agent 不能在运行中修改自己的提示词或技能。
- 改进走离线循环：出错 → 按 trace 定位 → 提出修改 → 用基准任务包回归 → 人工批准 → 发布新版本。

### A7 人工确认点（已确认）

| 环节 | 要求 |
|---|---|
| 需求基线 | 由人确认后才开始规划 |
| 方案采纳 | 由人确认 |
| 对外动作（询价、下单、发邮件） | 由人批准，Agent 只起草 |
| 规划中的歧义 | Copilot 可以暂停提问（A4） |

## 3. 已有方向、待细化

### B1 上下文（Context）

| 角色 | 能看到的 | 看不到的 |
|---|---|---|
| Copilot | 需求、各 Artifact 的结论摘要、未解决的缺口、项目历史摘要 | Specialist 的搜索过程和原始网页 |
| Specialist | 自己的 Brief、相关需求项、自己的技能、本次工具结果 | 其他 Specialist 的工作、整个项目的历史 |

- 长内容（PDF、整页参数）不直接放进上下文，先存为文件或证据，上下文中只放摘要和引用编号，需要时再读取。

### B2 技能（Skills）

- 技能 = 操作说明 + 确定性工具 + 测试用例。
- 带版本号；每个 Specialist 只能使用分配给它的技能。
- Artifact 记录所用技能的版本。

## 4. 待讨论

### C1 trace 的详细程度

已知的事实：

- **记录 trace 本身不消耗模型 token。** trace 只是把每次调用的输入、输出、耗时、token 数写进数据库，和写日志一样，花费的是存储空间，不是模型费用。
- 只有两种情况会因 trace 消耗 token：
  1. 用模型去**分析** trace，例如自进化循环里让模型总结失败原因。
  2. 把历史 trace 放回 Agent 的上下文。按 B1 的设计，不会这样做。

提议方案（待确认）：

- **骨架与内容分开存。** 骨架（运行 → 任务 → 每一步 → 模型调用 / 工具调用 / 规则校验，以及模型、token、耗时、费用、内容哈希）很小，永久保留；完整的输入输出按下表保留。
- **内容去重。** 系统提示词和技能说明只记版本号；工具返回的大段内容按哈希只存一份，已经作为证据保存的只记引用。
- **格式**：OpenTelemetry GenAI 规范，先存在 PostgreSQL 自建表里，在 P3 查看页面上以树状结构展示；以后需要时可以接入 Langfuse 等工具，不用改代码。
- **保留期限**：

  | 运行类型 | 完整内容保留 |
  |---|---|
  | 基准任务（考卷）运行 | 永久 |
  | 被标记为出错案例的运行 | 永久（A8 出题和自进化回归要用） |
  | 普通项目运行 | 90 天，之后只保留骨架 |

不论最终怎么选，**业务记录与 trace 之间的连接字段（运行 ID 等）都在 P1 预留**，见 P1 任务说明 3.8 节。

### C2 经验的遗忘方式

提议方案（待确认）：

- 每条经验有一个活跃度，由以下因素决定：多久没被检索或采用、被推翻的次数、类型（事实型衰减快，方法型衰减慢）。人工置顶的经验不参与遗忘。
- 活跃度低于阈值时**只降级不删除**：活跃 → 休眠（默认检索不到，但能搜到）→ 归档（只留作审计）。这样既保留审计记录，遗忘错了也能恢复。
- 实验室文档不参与自动遗忘，只支持“被新版本取代”和定期提醒人复查。
